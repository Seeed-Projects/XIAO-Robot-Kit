# 机甲小车 BLE 控制

## 设备名称

本设备的对话名称为**机甲小车**。所有小车烧录同一份固件，BLE 广播名称统一为
`XIAO-Robot-Kit-` 加 BLE 地址后两字节（如 `XIAO-Robot-Kit-3C7A`），机身标签印有该名称，
手机蓝牙设置里也能看到。两个 UUID 对所有小车固定不变：

```text
service_uuid="a2f39c10-7e4b-4d21-8a61-0f3bc9d15001"
characteristic_uuid="a2f39c11-7e4b-4d21-8a61-0f3bc9d15001"
```

### 确定名称（仅首次）

首次需要发指令、而上下文里还没有小车名称时，先请用户提供
名称的后四位（即 `XIAO-Robot-Kit-` 后面的四位，如 `3C7A`），把字母统一大写后拼成完整名称
`XIAO-Robot-Kit-<后四位>`，并告诉用户“将使用小车 `<完整名称>`”。用户若一开始就直接报出
完整名称或后四位（如“让 XIAO-Robot-Kit-3C7A 前进”），直接使用，不必再问。

名称确定后，本轮及之后所有 `ble_send_command` 都用这个 `device_name`，不再询问；
只有用户明确说“换一台”“换车”或报出新的后四位时才改用新名称。发送“停止”无需重新确认名称。

## 工具

- `ble_send_command`：向 ESP32 发送控制指令。
- `basicGimbal`：打开、关闭、停止或回零手机云台。
- `operateGimbal`：执行云台点头、摇头、抬头等预置拟人化动作。
- `generateGimbal`：执行持续或复杂的云台轨迹。
- `playMusic`：播放手机本地音乐或在线音乐。
- `operateMusic`：关闭、暂停、继续或重新播放当前音乐。
- `skill_exit`：BLE 配对、固件烧录、硬件接线或代码开发不属于本 skill 时使用。

## BLE 调用

所有命令使用以下参数。`device_name` 填入“设备名称”中确定的完整名称，其余参数固定不变：

```text
device_name="<上下文确定的完整设备名称，如 XIAO-Robot-Kit-3C7A>"
service_uuid="a2f39c10-7e4b-4d21-8a61-0f3bc9d15001"
characteristic_uuid="a2f39c11-7e4b-4d21-8a61-0f3bc9d15001"
encoding="utf-8"
ack_type="no_ack"
expect_response=false
```

下文出现“其余参数同固定参数”时，指的就是上面这组参数（`device_name` 用上下文确定的名称）。
将下表中的文本作为 `ble_send_command` 的
`command_array=[{"command":"<命令>","delay_ms":0}]` 发送。

## ESP32 内置动作指令

下表为无联动的内置动作，直接按意图发对应命令；带云台／音乐联动的动作见后续小节。

| 用户意图 | BLE 命令 |
| --- | --- |
| 前进 / 后退 | `move_forward` / `move_backward` |
| 左转一下 / 右转一下 | `turn_left` / `turn_right` |
| 顺时针 / 逆时针转一圈 | `spin_clockwise` / `spin_counterclockwise` |
| 挥手 | `wave_hand` |
| 握手 | `handshake` |
| 双臂展开 | `open_arms` |
| 双臂举起 | `raise_both_arms` |
| 双臂收拢 | `close_arms` |
| 停止手臂 | `armstop` |
| 停止全部动作 | `stop` |

## 对话触发

- 当用户说“打个招呼”“跟大家打招呼”或明确要求招呼、问候时，按“云台联动”中的“打招呼”流程执行。
- 当用户在招呼后评价“不够热情啊”“不够热情”“热情一点”“再热情些”“开心一点”等同义反馈时，按“云台联动”中的“开心”流程执行。

## 手动底盘速度

| 用户意图 | BLE 命令 |
| --- | --- |
| 指定左右轮速度 | `speed <left> <right>`，每个值范围为 `-100..100` |
| 前进 | `speed 60 60` |
| 后退 | `speed -60 -60` |
| 原地左转 | `speed -60 60` |
| 原地右转 | `speed 60 -60` |

手动 `speed` 会持续运行，用户要求停止或给出时长时才发送 `stop`。

## 云台联动

云台联动只加手机云台、不配音乐，动作与 BLE 命令一一对应：

| 动作 | 云台调用 | BLE 命令 |
| --- | --- | --- |
| 打招呼 | `operateGimbal(actionType="拟人化动作", emotionType="点头")` | `greeting` |
| 开心 | `generateGimbal(taskQuery="云台点头摇头交替执行八个节拍，结束后回到中位")` | `emotion_happy` |
| 害怕 | `operateGimbal(actionType="拟人化动作", emotionType="抬头")` | `emotion_scared` |
| 生气 | `operateGimbal(actionType="拟人化动作", emotionType="左转头")` | `emotion_angry` |

云台不由 ESP32 控制。执行前先调用 `basicGimbal(actionType="打开", target="云台")`，
打开成功后在同一轮并行调用对应的云台工具和 BLE 命令，不要等其中一项完成再启动另一项。
情绪类联动只调用一次 operateGimbal 原子动作：云台底层不支持时长/次数参数，generateGimbal
编多段长脚本会严重超出小车动作时长（见“同步设计原则”）。

收到“停止”或“停止跳舞”时，在同一轮并行发送 BLE `stop`、停止云台和关闭音乐。用户直接要求
云台基础操作时使用 `basicGimbal`；要求点头、摇头、抬头或转头时使用 `operateGimbal`；
复杂云台轨迹使用 `generateGimbal`。

## 同步设计原则

云台底层不支持时长或次数参数（无法让云台“点头 10 秒”或“点头 10 次”），
generateGimbal 对自然语言描述的时长执行得也不精确。为让小车与云台的启停尽量一致，
本 skill 遵循两条原则：

1. 短情绪动作（小车侧均在 3 秒内）：云台只调用一次 operateGimbal 拟人化原子动作，
   用原子动作的固定时长贴近小车时长；不要用 generateGimbal 编多段长脚本，否则云台会
   在小车结束后继续运动数秒（曾经给开心配“总时长至少 12 秒”的脚本，而小车约 2 秒就
   结束了，观感严重脱节）。
2. 长舞蹈：以音乐为主时钟，且整套联动必须在 agent 保活窗口（约 10 秒）内一次性下发完毕；
   之后不能安排任何"稍后停止/关闭"类步骤（agent 已下线，不会执行）。音乐使用自带静音尾
   的长文件（《New_Believer35》，前约 35 秒有声、其后约 300 秒静音，模拟暂停），有声部分
   播完即自动安静，无需也无法关闭；小车舞蹈按固定时长自动收尾；云台轨迹必须自带结尾回中，
   自行结束。云台轨迹的时长**用节拍结构描述、不要用秒数**（实测："至少 32 秒+16 组四拍"
   实际跑了约 30 秒、与 64 拍吻合；"总时长 40 秒以上"却跑出约 51 秒）：按 19 个四拍小节
   （76 拍 × 466ms ≈ 35.4 秒）编排，结尾小节固定减幅回中。若真机实测云台落点仍偏，只增减
   小节数即可（每小节约 1.86 秒）。
3. 节拍对齐靠**同轮下发**：BLE 舞蹈指令与 playMusic 必须同一轮并行下发且 BLE 在最前；
   分轮会让二者之间插入一轮 agent 思考（1~3 秒不确定延时），音乐先响、小车后动，必然错拍。
   固件 `start_delay_ms` 用来吸收音乐播放器的出声延迟，真机按 100ms 步进标定。

各 BLE 动作的小车侧实际时长（通用固件当前版本），编写或调整联动脚本时对照：

| BLE 命令 | 小车侧实际时长 |
| --- | --- |
| `greeting` | 约 3 秒 |
| `emotion_happy` | 约 2~2.5 秒（举臂挥舞 + IMU 转一圈，随地面与电量略有变化） |
| `emotion_scared` | 约 0.5~0.8 秒 |
| `emotion_angry` | 约 1 秒 |
| `reverse_park` | 约 8.9 秒（0.6 秒起步延时 + 5 小节分段扇形倒车，136 BPM），配《请注意倒车8s》 |
| `dance_new_believer` | 0.5 秒预备 + 约 35.9 秒舞蹈 + 短路径回正（通常 <1 秒），结束后自动停车收臂 |

## 倒车入库情景联动

“倒车入库”同时联动手机云台与音乐，BLE 指令与 playMusic 必须同轮下发且 BLE 在最前，
避免跨轮 agent 思考延时导致错拍；本流程之后不能依赖任何后续停止或关闭操作
（agent 保活窗口只有约 10 秒）。

0. **准备轮：确认上下文已有小车名称，没有则先按“设备名称”向用户询问拿到名称再开始；
   后续各轮不再询问。**
1. 第一轮，并行调用两项：
   - `basicGimbal(actionType="打开", target="云台")`；
   - `ble_send_command(command_array=[{"command":"stop","delay_ms":0}], 其余参数同固定参数)`：
     预热 BLE 链路并清理小车状态。
2. 第二轮，按以下先后顺序并行下发三项：
   - `ble_send_command(command_array=[{"command":"reverse_park","delay_ms":0}])`：小车 0.6 秒
     后按 136 BPM 鼓点分段扇形倒车（奇数小节倒车、偶数小节停顿观察），手臂随鼓点交替摆动，
     全程约 8.9 秒，音乐结束时停稳收臂；
   - `playMusic`：只播放手机**本地音乐**《请注意倒车8s》（前约 8.4 秒有声，其后为长静音、
     模拟暂停；有声部分播完即自动安静，无需也不要调用关闭播放；不得在线检索、循环、
     在舞蹈中重新播放或调用“重新播放”）；
   - `generateGimbal`：

     ```text
     generateGimbal(taskQuery="模拟人类倒车入库时回头看后方，严格按 5 个四拍小节执行（136 BPM，共 20 拍，约 8.8 秒）：第 1 小节，平稳转头看向右后方并微微抬头，像司机回头看后方路况；第 2 小节，保持回头看，强拍时轻轻点头一次；第 3 小节，保持回头看，轻微向另一侧扫视一次再回正后方；第 4 小节，继续回头看，强拍时再轻轻点头一次；第 5 小节，缓慢转头回中位，到最后第 20 拍时正好回到中位并保持静止。完成后一直保持中位，不要增加额外小节，中途不要自行回中或结束")
     ```

本流程到此为止：音乐约 8.4 秒后自动进入静音段，小车与手臂约 8.9 秒内自动停稳收臂，云台
第 5 小节自行回中并保持。若用户中途说“停止”，按“云台联动”中的停止流程并行发送 BLE
`stop`、停止云台、关闭音乐。

## 跳舞音乐与云台顺序

“跳舞”同时联动手机云台与音乐，严格按以下顺序执行。整套调用必须一次连续下发完毕
（agent 保活窗口只有约 10 秒），本流程之后不能依赖任何后续停止或关闭操作。

**决定节拍的两个调用（BLE 舞蹈指令、播放音乐）必须放在同一轮并行下发，且 BLE 写在最前。
两者若分属两轮，中间隔着一轮 agent 思考，会产生 1~3 秒不确定延时，此时音乐已经播放，
小车动作就会与音乐错拍。** generateGimbal 的文本很长，必须排最后，避免 BLE 指令堵在
它的生成后面。

0. **准备轮：确认上下文已有小车名称，没有则先按“设备名称”向用户询问拿到名称再开始；
   后续各轮不再询问。**
1. 第一轮，并行调用两项：
   - `basicGimbal(actionType="打开", target="云台")`；
   - `ble_send_command(command_array=[{"command":"stop","delay_ms":0}], 其余参数同固定参数)`：
     预热 BLE 链路并清理小车状态，避免下一条舞蹈指令承担蓝牙建连/重连延时。
2. 第二轮，按以下先后顺序并行下发三项：
   - `ble_send_command(command_array=[{"command":"dance_new_believer","delay_ms":0}])`：
     小车收到后延时 0.9 秒起步（等待音乐播放器出声；约 35.9 秒舞蹈，结束后自动短路径
     转回初始朝向并收臂停车）；
   - `playMusic`：只播放手机**本地音乐**《New_Believer35》（前约 35 秒有声，其后为长静音、
     模拟暂停；有声部分播完即自动安静，无需也不要调用关闭播放；不得在线检索、循环、
     在舞蹈中重新播放或调用“重新播放”）；
   - `generateGimbal`：

     ```text
     generateGimbal(taskQuery="为 128.7 BPM 的舞蹈伴奏，严格按 19 个四拍小节执行（共 76 拍）：第 1~8 小节主歌，每两拍随节奏左右平稳摇摆一次，每逢小节强拍轻快点头一次；第 9 小节间奏，减小摆幅、缓慢向中位收回一半；第 10~18 小节高潮，恢复大幅左右摇摆，每小节穿插一次快速点头或左右摇头；第 19 小节结尾，逐渐减小摆幅、缓慢回到中位并保持静止。76 拍跳完后一直保持中位静止，不要增加额外小节，中途不要回中或自行结束")
     ```

本流程到此为止，没有后续步骤：音乐约 35 秒后自动进入静音段，小车约 36 秒自动完成舞蹈、
回正与收臂，云台轨迹自带回中收尾、自行结束。若用户中途说“停止”，按“云台联动”中的
停止流程并行发送 BLE `stop`、停止云台、关闭音乐。
